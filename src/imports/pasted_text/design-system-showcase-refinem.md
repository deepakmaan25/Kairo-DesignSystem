VISUAL IMPROVEMENTS TO MAKE

1. USE THE ACTUAL DESIGN SYSTEM COLORS
The current version feels too black and white.
Introduce the semantic colors from the design system and apply them meaningfully.

Use color in these places:
- active navigation states
- token diagrams
- component state demos
- semantic feedback examples
- badges, tags, alerts, toggles, and state indicators
- section accents and subtle highlights
- illustration details or preview frames
- key moments in hero and transition states

Do not flood the whole website with color.
Most of the site should remain neutral and clean.
Use color with restraint and clarity so the system feels alive, not chaotic.

2. IMPROVE DARK MODE SURFACE HIERARCHY
The dark mode is currently too dark and too flat.
Black-on-black surfaces make section boundaries, cards, grids, and elevation hard to perceive.

Rework dark mode using a layered neutral hierarchy:
- page background = deep charcoal, not pure black
- section surface = slightly lighter
- cards and component panels = clearly lighter than section
- nested elements = one more step of elevation where needed
- overlay elements = visibly elevated from everything below
- borders = soft but visible
- grid lines = subtle and secondary
- shadows = soft and atmospheric, not muddy

Dark mode should feel premium and readable, not harsh.
The user should immediately be able to distinguish:
page background
section boundary
card surface
interactive surface
hover surface
overlay/modal surface

3. IMPROVE LIGHT MODE TOO
Even if the current issue is most visible in dark mode, also refine light mode so that:
- section separation feels intentional
- elevation examples are legible
- raised/floating/overlay/modal levels are clearly distinct
- cards don’t disappear into the page
- shadows feel soft and high quality
- borders are subtle but effective

4. REMOVE INTERNAL AUDIT MESSAGING FROM THE PUBLIC WEBSITE
Some areas currently mention missing or out-of-scope things using danger/alert styling.
Remove those messages from the visible site.

Do not show:
- out of scope
- missing from system
- candidate to add
- not defined yet
- temporary only
- future addition
- warning callouts about gaps

Those findings are useful for the designer privately, but should not appear in the public-facing experience.

If a pattern is missing, either:
- quietly simplify the public presentation, or
- implement a tasteful placeholder treatment without calling attention to incompleteness

5. REMOVE AI-SLOP / ROBOTIC COPY
Refine all text so it sounds calm, human, and professionally designed.
Avoid:
- excessive em dashes
- over-explaining interactions
- stiff mechanical microcopy
- abstract AI-ish phrases
- overuse of words like “immediate,” “decisive,” “orchestrated,” “systematic,” “scalable” unless genuinely useful

Rewrite copy to be:
- shorter
- cleaner
- more natural
- more elegant
- more editorial/product-design in tone

Examples:
Instead of:
“Changes take effect now — not on submit.”
Use:
“Takes effect immediately.”

Instead of:
“The thumb animates with a spring tuned to feel decisive but not snappy.”
Use:
“A soft spring gives immediate feedback.”

Keep labels and descriptions useful, but reduce friction and verbosity.
